# Output Modes

When converting a Cordova plugin to Capacitor, choose one of two output modes
up front. The choice changes file layout, `git mv` semantics, and what the
generator skill is told to do in Phase 11.

## Mode B — Side-by-Side (default)

Generate the Capacitor plugin in a sibling directory; the Cordova source is
not touched.

```
parent/
├── cordova-plugin-foo/         # original, untouched
└── capacitor-plugin-foo/       # new, generated by capacitor-plugin-generator
```

**When to use:**

- The Cordova plugin is read-only (vendored, dependency, archived).
- The Cordova plugin is published from a different repo than the planned
  Capacitor plugin.
- The user wants the original source intact for diff-based review.
- The user has not explicitly opted into Mode A.

**Handoff hint to the generator:**

```yaml
migration:
  output_mode: side_by_side
```

The generator scaffolds into `capacitor-plugin-<name>/` using the official
`npm init @capacitor/plugin` flow; nothing inside `cordova-plugin-<name>/` is
written.

## Mode A — In-Place with `.cordova-archive/`

Move the Cordova source into a hidden `.cordova-archive/` subdirectory of the
original plugin directory, then scaffold the Capacitor plugin in the cleared
root. The original directory keeps its name and its commit history.

```
my-plugin/
├── .cordova-archive/           # was the original layout
│   ├── plugin.xml
│   ├── www/
│   └── src/
├── android/                    # new Capacitor plugin
├── ios/
├── src/
└── package.json
```

**When to use:**

- The user explicitly asks for in-place migration.
- The plugin directory is the only source of truth and is under version
  control.
- The user wants `git log --follow` to keep tracking the directory.

**Pre-flight checks (refuse Mode A if any fail):**

1. Working tree is a git repo with no uncommitted changes in the plugin
   directory.
2. The plugin directory is writable.
3. No directory named `.cordova-archive` already exists in the plugin root.

**Recommended `git mv` pattern:**

```bash
cd my-plugin
mkdir .cordova-archive
git mv plugin.xml .cordova-archive/plugin.xml
git mv www .cordova-archive/www
git mv src .cordova-archive/src
# Repeat for every top-level Cordova artifact.
git commit -m "chore: archive Cordova source under .cordova-archive/"
```

After the move, run `capacitor-plugin-generator` against the now-cleared
directory. Anything the generator writes goes into a clean root.

**Handoff hint to the generator:**

```yaml
migration:
  output_mode: in_place
```

## Choosing the Mode

| Question | Mode B (side-by-side) | Mode A (in-place) |
| --- | --- | --- |
| Need original source intact? | ✅ Yes | ❌ Moved under `.cordova-archive/` |
| Need `git log --follow` to keep working on the directory name? | ❌ Different directory | ✅ Same directory |
| User opted in explicitly to in-place? | ❌ No | ✅ Yes |
| Working copy is read-only or non-VCS? | ✅ Allowed | ❌ Refuse Mode A |
| Plugin directory has uncommitted changes? | ✅ Allowed | ❌ Refuse Mode A |

Default to Mode B whenever any answer is unclear. The cost of a sibling
directory is small; the cost of an unrecoverable in-place move is large.

## What the Skill Reports After Mode A

After the archive move, surface:

- The `.cordova-archive/` path so reviewers can diff.
- A one-line note in the Phase 10 checkpoint: *"Original Cordova source is
  preserved under `.cordova-archive/`. The Capacitor generator will populate
  the cleared root."*
- A pointer to add `.cordova-archive/` to the published-package ignore list
  (`.npmignore` or `files` field) so it does not ship to npm.

## What the Skill Reports After Mode B

Surface:

- The target Capacitor directory path (`capacitor-plugin-<name>/`).
- A reminder that the original `cordova-plugin-<name>/` is not modified and
  will not be removed by the generator.
- A note for the consumer-facing changelog: the Capacitor package is a new
  npm artifact, not an in-place upgrade of the Cordova package.
